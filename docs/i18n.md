# UI internationalization (i18n)

The templates dex renders for the login, consent, MFA, device and logout pages are
localized on the server. English and Chinese ship with the server; embedders can add
or override any string, and add whole locales, without patching dex.

## How the language is picked

For every request the locale is resolved in this order:

1. `?lang=<tag>` query parameter — e.g. `/auth?lang=zh`
2. `dex_lang` cookie
3. `Accept-Language` request header (q-values honoured; `zh-CN` matches `zh`)
4. English

Only tags with a dictionary are selectable; anything else is ignored and the next
source is tried.

## Using it in templates

Every template data struct embeds `i18nData`, which provides:

```html
<html lang="{{ .Locale }}">
<h2>{{ .T "logInTitle" }}</h2>
<span>{{ .T "logInWith" $c.Name }}</span>
<span>{{ .T "invalidCredentials" .UsernamePrompt }}</span>
```

* `.T "key"` returns the message for the request locale.
* `.T "key" arg1 arg2` formats the message with `fmt.Sprintf`, so dictionaries use
  `%s` / `%d` placeholders.
* Inside a `{{ range }}` the dot is the loop item — use `{{ $.T "key" }}` to reach
  the page data (see `login.html`).
* `.Locale` is the resolved language tag, suitable for `<html lang="…">`.

Lookup order for a message: requested locale → English → the key itself. A missing
entry therefore renders the key rather than an empty string.

## Adding or overriding strings

Operators configure `WebConfig.Translations`, keyed by language tag:

```go
server.Config{
    Web: server.WebConfig{
        Translations: map[string]map[string]string{
            "zh": {
                "logInTitle": "登录你的账号",
                "logInWith":  "使用%s登录",
            },
            // a tag with no bundled dictionary becomes selectable as well
            "de": {"logInTitle": "Anmelden"},
        },
    },
}
```

Entries override the bundled dictionaries per key. To add a language to the bundled
set, add a map to `defaultTranslations` in `server/i18n.go` and list it in
`SupportedLocales`.

## Custom templates

Embedders that replace the templates (for example a branded login page) get the same
mechanism: call `.T` from the custom templates and pass the strings through
`WebConfig.Translations`. Strings that are not in a dictionary fall back to English,
so a partially translated custom template stays usable.

Connector names and username prompts are shown as configured on the connector — they
are operator data, not UI copy, and are not translated by dex.
